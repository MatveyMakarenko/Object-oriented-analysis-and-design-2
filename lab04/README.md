# Лабораторная 4. 

Каталог фильмов (CineCatalog)

Паттерн: Ленивая загрузка (Lazy Loading)

## Проблема:

Проблема заключается в том, что при отображении каталога фильмов с богатой метадатой (каст, рейтинги, пользовательские отзывы, описания) традиционный подход загружает все связанные данные сразу при инициализации приложения. При увеличении объёма базы (сотни фильмов, тысячи актёров и отзывов) это приводит к длительному времени первоначальной загрузки, высокому потреблению оперативной памяти на клиенте и избыточному сетевому трафику. Пользователь видит только список названий, но система уже потратила ресурсы на загрузку данных, которые могут никогда не понадобиться. Это нарушает принципы эффективности и масштабируемости, усложняет поддержку backend-логики и ухудшает пользовательский опыт на мобильных устройствах или при нестабильном соединении.
## Решение:
В проекте паттерн Lazy Loading используется для отложенной загрузки «тяжёлых» связанных данных (актёров и отзывов) до момента явного запроса со стороны пользователя. Вместо возврата единого массива со всей информацией при старте, сервер отдаёт только лёгкий список фильмов (ID, название, год, жанр). Детальная информация подгружается отдельным асинхронным запросом только тогда, когда пользователь выбирает конкретный фильм. Это позволяет разделить инициализацию интерфейса и получение контента, оптимизировать использование ресурсов и обеспечить мгновенный отклик приложения.

## Описание:

Система представляет собой веб-каталог из 50 известных фильмов с реальными составами актёров и сгенерированными отзывами. Пользователь видит быстрый список всех фильмов и строку поиска. При клике на карточку фильма интерфейс отправляет запрос на сервер, который возвращает полное описание, список актёров с ролями и пользовательские отзывы. Загруженные данные сохраняются в локальном кеше браузера, поэтому повторный переход к уже открытому фильму происходит мгновенно без дополнительных сетевых обращений. Архитектура чётко разделена на лёгкий endpoint списка и детальный endpoint с отложенной подгрузкой связанных сущностей.

Процесс организации доступа к данным реализуется с помощью паттерна Ленивая загрузка (Lazy Loading):

Movie — базовая модель фильма, содержащая только лёгкие атрибуты (movieid, title, year, genre, runtime, description). При создании объекта не хранит списки актёров и отзывов.

Actor и Review — модели связанных сущностей, инстанцируемые только при необходимости.

ActorsLoad и ReviewsLoad — классы-загрузчики, инкапсулирующие SQL-логику выборки связанных данных из базы по идентификатору фильма. Реализуют принцип единственной ответственности.

ApiServer — веб-сервер, предоставляющий два независимых эндпоинта:

• /api/movies — возвращает только метаданные списка (быстро, ~5-10 KB)

• /api/movie/{id} — создаёт объект Movie, вызывает методы movie.GetActors() и movie.GetReviews(), инициируя реальную загрузку из БД только в этот момент.

Клиентская часть (index.html) управляет состоянием интерфейса: отображает список сразу, а при выборе фильма инициирует подгрузку деталей, сохраняя результат в объект-кеш для повторного использования в рамках сессии.

Результат — высокопроизводительный каталог, обеспечивающий мгновенную отрисовку интерфейса независимо от объёма базы данных. Потребление трафика сокращается на 70–90% при типичном сценарии просмотра (пользователь открывает лишь несколько фильмов из списка). Система легко масштабируется на тысячи записей без деградации скорости старта. Пользователь получает плавный UX: список доступен сразу, а детализация подгружается незаметно в фоне, с возможностью мгновенного возврата к уже просмотренным позициям благодаря клиентскому кешированию.
