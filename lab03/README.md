# Лабораторная 3. 

Менеджер Задач (TaskFlow Manager)

Паттерн: Итератор

## Проблема:

Проблема заключается в том, что при работе с коллекцией задач требуется множество различных способов перебора элементов для разных сценариев использования (просмотр всех задач, только активных, сортировка по приоритету, фильтрация по категории). При реализации всех вариантов перебора внутри класса коллекции нарушается принцип единственной ответственности (SRP), класс разрастается методами. Это приводит к нарушению принципа открытости/закрытости (OCP) — при добавлении нового способа перебора требуется модификация существующего класса коллекции, усложнению тестирования логики перебора и невозможности независимого изменения способов доступа к данным без влияния на структуру хранения.
## Решение:
В проекте паттерн Iterator используется для отделения логики обхода и фильтрации элементов коллекции от самой коллекции. Вместо того чтобы заставлять TaskManager возвращать готовые списки в различных конфигурациях, мы создаем отдельные объекты-итераторы.

Каждый итератор инкапсулирует свой алгоритм доступа к данным. TaskManager выступает в роли фабрики, создавая нужный итератор по запросу. Графический интерфейс работает с итератором через единый интерфейс (has_next, next), не заботясь о том, как именно данные отфильтрованы или отсортированы.
## Описание:

Система позволяет пользователю создавать задачи с параметрами (название, категория, приоритет, статус), после чего просматривать коллекцию задач различными способами через паттерн Итератор:

•	Коллекция задач (TaskManager) — хранит список всех задач, не содержит логики фильтрации и сортировки

•	AllTasksIterator — перебор всех задач в порядке добавления (для общего списка)

•	ActiveTasksIterator — перебор только незавершённых задач (статус ≠ «Готово»)

•	PriorityTasksIterator — перебор задач, отсортированных по приоритету (Высокий → Средний → Низкий)

•	CategoryTasksIterator — перебор задач определённой категории (например, «Работа», «Дом», «Учёба»)

Для каждого типа итератора определяется общий интерфейс, который позволяет клиенту (GUI) работать с ними единообразно, не зная внутренней реализации перебора.

Процесс организации доступа к задачам реализуется с помощью паттерна Итератор (Iterator):

1.Iterator — базовый интерфейс итератора, определяющий методы has_next(), next(), previous(), reset(), current_index(), total()

2.Конкретные итераторы (AllTasksIterator, ActiveTasksIterator, PriorityTasksIterator, CategoryTasksIterator) реализуют различные стратегии перебора коллекции

3.TaskCollection — интерфейс коллекции с методом create_iterator()

4.TaskManager — конкретная коллекция, хранящая задачи и создающая нужный тип итератора по запросу

5.Task — модель задачи с атрибутами (title, category, priority, status, duration)

Результат — гибкая система просмотра задач с возможностью переключения режимов отображения без изменения класса коллекции, отображаемая в GUI с возможностью добавления/удаления/редактирования задач.

В рамках одного сеанса работы программы пользователь может переключаться между режимами просмотра задач (все/активные/по приоритету/по категории) без перезапуска приложения, формируя индивидуальное представление коллекции для текущей задачи.
