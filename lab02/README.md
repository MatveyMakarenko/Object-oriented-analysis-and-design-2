# Лабораторная 2. 
Диспетчер Умного Дома (SmartHome Hub)

Паттерн: Декоратор
## Описание проблемы:
 В системе умного дома имеются различные устройства (освещение, термостат, замок), которые необходимо оснащать дополнительными функциями: учётом энергопотребления, отправкой уведомлений о включении/выключении и работой по расписанию. При использовании наследования для реализации всех возможных комбинаций потребовалось бы создать экспоненциальное количество классов: LightWithEnergy, LightWithNotification, LightWithTimer, LightWithEnergyAndNotification, LightWithEnergyAndTimer, LightWithNotificationAndTimer, LightWithEnergyAndNotificationAndTimer и так далее для каждого из трёх типов устройств. В итоге для трёх базовых устройств потребовалось бы 21 класс (3 базовых + 18 комбинаций). Кроме того, пользователь должен иметь возможность динамически включать и отключать функции в процессе эксплуатации, что невозможно при статическом наследовании, так как функциональность жёстко фиксируется на этапе компиляции. Также возникает проблема дублирования кода: логика подсчёта энергии или отправки уведомлений повторялась бы в каждом классе, нарушая принцип единственной ответственности и принцип открытости/закрытости (OCP).
## Решение:
В проекте паттерн Decorator используется для динамического добавления обязанностей объектам устройств без изменения их классов. Вместо создания новых подклассов для каждой комбинации функций, система оборачивает базовый объект устройства в декораторы, каждый из которых добавляет свою функциональность. Это позволяет гибко компоновать устройства: одно и то же устройство может быть просто лампочкой, лампочкой с учётом энергии, лампочкой с уведомлениями или лампочкой со всеми функциями одновременно — в зависимости от конфигурации, выбранной пользователем через веб-интерфейс.

### Общая структура паттерна
IDevice — определяет общий интерфейс для всех устройств и декораторов (методы Activate(), Deactivate(), GetStatus()).

Light, Thermostat, Lock — базовые компоненты (конкретные устройства).

DeviceDecorator — абстрактный базовый класс декоратора, хранит ссылку на декорируемый объект типа IDevice и делегирует ему все вызовы.

EnergyDecorator, NotifyDecorator, TimerDecorator — конкретные декораторы, каждый из которых добавляет свою функциональность: EnergyDecorator отвечает за учёт энергопотребления, NotifyDecorator — за ведение
счёта включений/выключений и отправку уведомлений, TimerDecorator — за управление расписанием работы.
