# ОТЧЕТ

Диспетчер Умного Дома (SmartHome Hub)

 ## Проблема:
  
Проблема заключается в том, что создание конфигурации устройств «Умного дома» требует обеспечения строгой совместимости компонентов внутри одной экосистемы. При этом протоколы связи, формат данных и функционал кардинально отличаются в зависимости от производителя (например, премиум-экосистема требует шифрования и расширенной телеметрии, а бюджетная — базового управления). Использование простого условного кода для создания устройств приведет к нарушению принципа открытости/закрытости (OCP), усложнению кода при добавлении новых вендоров и риску несовместимости устройств разных производителей в рамках одной сессии управления.

Пример из кода (без паттерна):
// ❌ Нарушение OCP: для нового вендора нужно менять этот класс
if (currentVendor == "EcoHome")
{
    ecoLight = new EcoLight();
    ecoThermostat = new EcoThermostat();
}
else if (currentVendor == "TechPro")
{
    techLight = new TechLight();
    techThermostat = new TechThermostat();
}


##  Цель:
  
Разработать информационную систему с графическим интерфейсом, позволяющую пользователю выбирать экосистему оборудования (вендора) и управлять совместимым набором устройств (свет, термостат, замок), с возможностью экспорта текущей конфигурации и логов событий.

##  Описание:
  
Система позволяет пользователю выбрать профиль оборудования (например, «Бюджетный EcoHome», «Премиум TechPro»), после чего автоматически инициализируется соответствующий набор компонентов:

  •	Умное освещение (Light)
  
  •	Умный термостат (Thermostat)
  
  •	Умный замок (Lock)
  
Для каждого профиля определяется свой набор классов устройств, реализующих общие интерфейсы, но имеющих разную внутреннюю логику (например, премиум-замок ведет журнал доступа, а бюджетный — только меняет статус).

Процесс создания устройств реализуется с помощью паттерна Абстрактная Фабрика (Abstract Factory):

  1.	DeviceFactory - абстрактная фабрика, объявляющая методы создания продуктов.
  2.	Конкретные фабрики (EcoHomeFactory, TechProFactory) реализуют логику создания устройств конкретного вендора.
  3.	Абстрактные продукты (Light, Thermostat, Lock) определяют интерфейсы устройств.
  4.	Конкретные продукты (EcoLight, TechLight) реализуют функционал для конкретного вендора.
  5.	Результат — семейство объектов устройств, отображаемых в GUI, которое можно экспортировать как отчет (JSON).
     
В рамках одного сеанса работы программы пользователь может переключаться между конфигурациями разных вендоров без перезапуска приложения.
